# Проверка безопасности — 2 ноября 2026

Публичная версия отчёта о проверке исходников, локальных зависимостей, конфигурации установки и тестового развёртывания. Адрес сервера, локальные пути и индивидуальные сведения об инфраструктуре исключены.

Прямой путь к выполнению команд на VPS или чтению его файлов через проверенные функции приложения не обнаружен. Это ограниченный аудит приложения, а не доказательство отсутствия всех уязвимостей VPS.

**После аудита подготовлено локальное исправление.** Импорт и экспорт файлов удалены, сохранение в localStorage и миграция прежних данных сохранены. Обновлены зависимости и добавлены защитные HTTP-заголовки в Caddy, Nginx и локальный production-preview. Для применения на VPS нужен новый архив и `secure-update-ip.sh`; удалённая конфигурация агентом не изменялась. [Команды обновления](deploy/ip/README.md#управление-и-обновление).

## Подтверждённые свойства

- На сервере раздаются статические HTML/JS/CSS/шрифты/иконки. У приложения нет серверных обработчиков импорта, загрузки файлов, команд, базы данных или API.
- Локальное сохранение обрабатывается в браузере. Проверяются версия, типы, диапазоны, уникальность ID и длины строк; размер сохранения ограничен 32 КБ. Неизвестные поля не копируются в состояние. Файлы больше не импортируются и не экспортируются. В обновлении от 9 ноября добавлены `gameEdition` и два зарезервированных слота: максимум остаётся 32 обычных предмета плюс один наёмник и один скакун (34 записи суммарно).
- В коде приложения не обнаружены `eval`, `new Function`, `dangerouslySetInnerHTML` и вставка пользовательских строк через `innerHTML`. Названия предметов выводятся средствами React как текст.
- В отдельном браузерном профиле проверено имя предмета с HTML-обработчиком события: оно осталось текстом, HTML-элемент не появился и JavaScript не исполнился. Дополнительное поле `__proto__` не изменило прототипы. Эти проверки не меняли серверные или пользовательские сохранения.
- HTTPS доступен с обычной проверкой сертификата.
- Пять GET-запросов к `/.env`, `/.git/config`, `/Caddyfile` и двум вариантам обхода к `/etc/passwd` вернули тот же HTML приложения. Выдача этих файлов не обнаружена. HTTP 200 здесь — SPA fallback, а не подтверждение существования файла.

## Ограничения поставляемой службы

Таблица описывает шаблон установки, а не настройки какого-либо публичного сервера. На своей установке проверьте их через `systemctl show munchkin-hero` и права файлов через `stat`.

| Свойство | Значение |
| --- | --- |
| Пользователь / группа службы | `munchkin-web` / `munchkin-web` |
| Повышение привилегий | `NoNewPrivileges=yes` |
| Системные каталоги | `ProtectSystem=strict` |
| Домашние каталоги | `ProtectHome=yes` |
| Capability службы | только `cap_net_bind_service` |
| Лимит памяти | 268435456 байт, 256 МиБ |
| Корень сайта | `755 root:root` |
| Главная HTML-страница | `644 root:root` |

Процесс сайта не получает root-доступ, а файлы сайта недоступны ему для записи. Ограничения службы снижают последствия возможной уязвимости веб-сервера; они не заменяют исправления ОС и не являются полной изоляцией сети или ядра.

В поставляемом Caddyfile отключён admin API, нет PHP/FastCGI, обратного проксирования и шаблонного выполнения кода. Ссылки в корне сайта потенциально могут вести за его пределы: это поведение самого файлового сервера Caddy. Текущий скрипт обновления отклоняет символические ссылки. [Документация Caddy](https://caddyserver.com/docs/caddyfile/directives/file_server).

## Найденные замечания

### 1. Известные проблемы в инструментах сборки

`npm audit --omit=dev --json` сообщил **0** известных уязвимостей production-зависимостей. Это результат базы npm на дату проверки, а не гарантия отсутствия неизвестных ошибок.

До исправления полный `npm audit --json` сообщил 11 затронутых пакетов: 1 high, 8 moderate, 2 low. Часть записей относится к цепочкам одного и того же уязвимого транзитивного пакета.

- `sharp@0.34.5`: несколько high-advisories в нативных библиотеках. Для актуального замечания librsvg исправление указано в 0.35.5. [Advisory sharp](https://github.com/advisories/GHSA-wq5f-xc86-pv6w).
- Цепочка `vite-plugin-pwa` → `workbox-build`: проблемы `glob`, `minimatch`, `deepmerge` и зависимых инструментов. [glob](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4), [minimatch](https://github.com/advisories/GHSA-g3hv-75wg-m249), [deepmerge](https://github.com/advisories/GHSA-gcqx-w48m-w2h4).

Исправлено: `sharp` обновлён до 0.35.5, `vite-plugin-pwa` до 2.0.0; для `workbox-build` закреплены `glob` 14.0.3 и `@trickfilm400/rollup-plugin-off-main-thread` 4.0.0, `minimatch` обновлён до 11.0.4. Новый плагин также убрал старую цепочку EJS/Jake. Lock-файл пересоздан и установка из него проверена. Аудит при установке включён; `npm run audit` останавливается при известных проблемах moderate/high/critical.

После исправления: **0 critical, 0 high, 0 moderate, 4 low** во всём дереве; **0** в `npm audit --omit=dev`. Четыре low-записи относятся к одной проблеме `deepmerge@4.3.1` и зависимым пакетам `@rollup/plugin-node-resolve`, `workbox-build`, `vite-plugin-pwa`. Исправленной версии deepmerge в advisory пока нет. Он используется в инструменте разрешения модулей при локальной сборке; это не серверный обработчик и на VPS не устанавливается. Остаётся ограничение: собирать только доверенный исходный код и конфигурацию. `npm audit fix --force` предлагает откатить PWA-плагин до 0.2.1; такой откат не применён. [Состояние исправления deepmerge](https://github.com/advisories/GHSA-gcqx-w48m-w2h4).

### 2. Нет дополнительных защитных HTTP-заголовков

При первоначальном аудите на опубликованной странице отсутствовали `Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options` и `Referrer-Policy`.

В локальной версии добавлены CSP для ресурсов с того же адреса без `unsafe-inline`/`unsafe-eval`, запрет встраивания, `nosniff`, `Referrer-Policy: no-referrer` и запрет камеры/микрофона/геолокации через Permissions-Policy. Исправлено наследование заголовков в Nginx: локальные `add_header Cache-Control` больше не отменяют общие защитные заголовки. Проверены настоящие ответы Caddy, шрифты, Service Worker, офлайн-перезагрузка и обновление PWA. Отдельный браузерный тест подтвердил блокировку встроенного скрипта CSP и текстовый вывод HTML-подобного имени предмета. [CSP в документации MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP), [заголовки Caddy](https://caddyserver.com/docs/caddyfile/directives/header).

`secure-update-ip.sh` перед изменением сравнивает конфигурацию с известными шаблонами, проверяет новую через `caddy validate`, сохраняет копии сайта/Caddyfile и перезапускает только `munchkin-hero`. При ошибке запуска или HTTPS-проверки восстанавливается прежний Caddyfile. Изменённые вручную настройки не перезаписываются автоматически. Сценарии отказа, повтора и отката проверены в одноразовом контейнере с подменой systemctl; настоящий перезапуск systemd на VPS должен выполнить владелец. **Заголовки на работающем сервере появятся после применения обновления.**

Проверки исправления: 55 модульных тестов, 14 браузерных тестов, TypeScript, production-сборка и генерация иконок. Браузерные проверки выполнены под указанной CSP, включая экраны 320×568, сохранения и офлайн-запуск.

### 3. Доступность при сетевой атаке остаётся отдельным риском

Статический сайт тоже можно перегрузить запросами, TLS-соединениями или входящим трафиком. Лимит памяти относится к процессу приложения, а сетевой канал и ресурсы ядра общие с VPN/telemt. Защита от объёмного DDoS должна действовать до узкого места канала, обычно у провайдера. Нагрузочные и DoS-проверки на работающем VPS не выполнялись.

## Границы проверки

Для распространения через GitHub 9 ноября подготовлены обезличенные документы и архивы: без адреса владельца, локальных путей, Git-истории и частных резервных копий. Упаковка использует явный список файлов и предварительную проверку распространённых секретов. Содержимое трёх итоговых архивов и их контрольные суммы проверяются отдельно; метаданные владельца файлов заменяются стандартными. Проверка по правилам не гарантирует обнаружения любых личных сведений в будущем.

Мастер `setup.sh` проверяет контрольные суммы файлов пакета, предлагает установку, обновление и управление только `munchkin-hero`. Удаление требует подтверждения, сохраняет прежние файлы и сертификаты и отклоняет изменённый unit. В одноразовом контейнере без сети проверены отказ при некорректном IP, занятом 80 и неверной сумме Caddy/файлов сайта, новая установка, отказ при повторной установке, резервная копия при обновлении, сохранение старых ресурсов, подтверждение/отмена удаления и сохранение отдельного listener на 443. Systemd и загрузка Caddy в этих сценариях подменены тестовыми командами; конфигурацию проверяет настоящий Caddy. Настоящий запуск systemd и выдачу сертификата на новом сервере проверяет его владелец.

Обучение и встроенная документация добавлены 9 ноября 2026 года. Урок использует отдельное состояние героя в памяти и отдельный ключ `munchkin.tutorial.v1` для отметки просмотра. Учебные действия не передаются в сохранение партии. Браузерные проверки сравнивают исходную строку сохранения до, во время и после урока, включая выход, повторный запуск и перезагрузку. Справка поставляется в сборке и работает офлайн. Политика CSP и конфигурация VPS для этих функций не ослаблялись; геометрия подсказок задаётся через свойства CSSOM, что проверено под действующей CSP.

- SSH-конфигурация, firewall, ядро Ubuntu, обновления пакетов, панель управления и telemt/Xray целиком не проверены.
- Работоспособность сайта не подтверждает безопасность других служб на том же IP.
- Сверены опубликованные advisories Caddy; просмотренные проблемы исправлены в версиях до закреплённой 2.11.7 либо относятся к неиспользуемым обработчикам. Это не полный анализ встроенного Go-runtime и всех компонентов ОС. [Advisories Caddy](https://github.com/caddyserver/caddy/security/advisories).
- Пароли, SSH-ключи и приватные сертификаты не запрашивались. Исправления сделаны в локальном проекте и готовом архиве; доступ по SSH и изменение конфигурации работающего VPS агентом не выполнялись.
