# Ubuntu: PWA по IP на 8443 рядом с сервисом на 443

Готовая схема для IPv4 на HTTPS-порту 8443. Во всех примерах `203.0.113.10` — адрес только для документации: замените его своим публичным IPv4. Используется Caddy 2.11.7 из официального релиза, без apt-установки веб-сервера, Docker и Node.js на VPS.

Для новой установки удобнее мастер `bash setup.sh` из готового архива; [краткая инструкция](../../INSTALL.md). Внутри установочного архива см. `INSTALL.md` рядом с мастером. Приведённые ниже команды остаются доступны отдельно.

Подготовленные файлы рассчитаны на Ubuntu 24.04 с systemd и x86_64/arm64. Скрипт создаёт отдельную службу `munchkin-hero`, пользователя `munchkin-web`, приложение в `/opt/munchkin-hero`, данные сертификатов в `/var/lib/munchkin-hero`. Перед установкой проверяются зависимости, свободные 80/8443 и отсутствие прежней установки. Контрольная сумма скачанного Caddy сверяется с официальным релизом.

## Перед запуском

- TCP 80 и 8443 должны быть свободны и доступны извне. TCP 80 нужен для первоначальной выдачи **и продления** IP-сертификата. Службы на 443 остаются на своих портах.
- Установщик не открывает порты и не меняет firewall. Если UFW активен, добавьте разрешения только для TCP 80 и 8443; сохраните действующие SSH/VPN-правила. Аналогично проверьте firewall/security group у провайдера. Не включайте UFW заново и не сбрасывайте его конфигурацию ради установки.
- Нужны `curl`, `tar`, `sha256sum`/`sha512sum` из coreutils, `ss`, `systemctl` и обычные системные утилиты. Если их нет, установщик остановится до установки приложения. `curl` при необходимости ставится отдельно, например `apt-get update` и `apt-get install --no-install-recommends curl ca-certificates`.
- Для получения сертификата принимаются условия Let's Encrypt; сайт и IP попадут в публичные журналы Certificate Transparency, как при обычной публичной выдаче TLS-сертификатов.

Let's Encrypt выдаёт IP-сертификаты с профилем `shortlived`, сроком 160 часов. Caddy запрашивает именно этот профиль и автоматически продлевает сертификат. Проверка TLS-ALPN на 443 отключена, используется HTTP-01 на 80. Caddy admin API отключён, публичное приложение слушает TCP 8443; UDP/HTTP3 отключён. В systemd для новой службы дополнительно запрещено занимать TCP/UDP 443; это ограничение относится только к ней, а не к другим процессам.

Источники: [IP-сертификаты Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability), [параметры ACME в Caddy](https://caddyserver.com/docs/caddyfile/directives/tls), [установка статического Caddy](https://caddyserver.com/docs/install#static-binaries).

## Загрузка и запуск

На компьютере, в PowerShell в папке проекта:

```powershell
scp .\artifacts\munchkin-vps-ip.tar.gz root@203.0.113.10:/root/
```

Пароль вводится только в локальном запросе SSH/SCP. На VPS используйте отдельный каталог для распаковки. Пример для первой установки, когда `~/munchkin-upload` ещё не существует:

```bash
mkdir ~/munchkin-upload
tar -xzf ~/munchkin-vps-ip.tar.gz -C ~/munchkin-upload
cd ~/munchkin-upload
bash install-ip.sh 203.0.113.10
```

Скрипт запускайте от root либо через sudo. Если каталог распаковки уже существует, выберите другой пустой каталог. Нельзя распаковывать архив поверх чужой программы или работающего сайта.

## Проверка

```bash
systemctl status munchkin-hero --no-pager
journalctl -u munchkin-hero -n 50 --no-pager
ss -lntp | grep -E ':(80|443|8443)\b'
curl -I https://203.0.113.10:8443/
```

Выпуск сертификата занимает некоторое время. Успешный `curl` без `-k` подтверждает доверенный TLS. Если есть ошибка сертификата, не обходите её для установки PWA: проверьте журнал, доступность TCP 80 извне и часы VPS. По HTTP интерфейс доступен, но Service Worker на публичном IP не работает; используйте конечный HTTPS-адрес.

Проверьте, что процесс на 443 остался прежним, и проверьте свой VPN/прокси тем же клиентом. Откройте приложение на телефоне, дождитесь «Готово к офлайну», затем добавьте его на главный экран и проверьте авиарежим.

Если порт 80 недоступен извне и нельзя его открыть, эта схема выпуска IP-сертификата не подойдёт. DNS-01 не подтверждает владение IP. Тогда нужен другой доступный HTTP-01 вход либо переход к домену и подходящей проверке сертификата.

## Управление и обновление

Для текущего обновления с защитными заголовками используйте **secure-update-ip.sh**. На компьютере в PowerShell:

```powershell
scp .\artifacts\munchkin-vps-ip.tar.gz root@203.0.113.10:/root/
ssh root@203.0.113.10
```

Следующие команды выполняются **после входа на VPS**, когда приглашение начинается с `root@`, а не `PS`:

```bash
upload_dir=$(mktemp -d /root/munchkin-security.XXXXXX)
tar -xzf /root/munchkin-vps-ip.tar.gz -C "$upload_dir"
bash "$upload_dir/secure-update-ip.sh" 203.0.113.10
curl -I https://203.0.113.10:8443/
```

Скрипт проверяет соответствие текущего Caddyfile стандартной прежней или новой конфигурации для указанного IP. Сравниваются разобранные конфигурации: пробелы и комментарии не мешают проверке. Изменённые вручную виртуальные хосты, прокси или настройки TLS автоматически не перезаписываются — скрипт остановится до обновления файлов.

Затем проверяется новая конфигурация, создаются резервные копии сайта и Caddyfile, публикуются новые файлы и защитные заголовки. Перезапускается только `munchkin-hero`, так как её admin API отключён. При ошибке запуска или HTTPS-проверки возвращается прежний Caddyfile и повторяется запуск этой службы; новые файлы сайта остаются, их копия предыдущей версии доступна в `backups/site.*`. Сертификаты в `/var/lib/munchkin-hero`, бинарник Caddy, systemd, firewall и службы на 443 не изменяются. Возможен короткий перерыв только у приложения.

В ответе `curl -I` должны присутствовать `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` и `Permissions-Policy`. CSP разрешает ресурсы приложения с того же адреса, запрещает встроенные скрипты и встраивание во фрейм. Она проверена с локальными шрифтами, офлайн-запуском и обновлением Service Worker. Импорт и экспорт файлов удалены; автоматическое сохранение партии на устройстве остаётся.

Если служба не работает, прочитайте `journalctl -u munchkin-hero -n 50 --no-pager`. Не запускайте заново установщик поверх существующего приложения.

Обычные команды управления:

```bash
systemctl stop munchkin-hero
systemctl start munchkin-hero
systemctl restart munchkin-hero
```

Эти команды управляют только новым сайтом. Не удаляйте `/var/lib/munchkin-hero`: там ключи, сертификаты и данные ACME для продления. Сертификаты не включаются в архив приложения.

Повторный запуск установщика не перезаписывает существующую установку. Для последующих обновлений **только файлов сайта**, когда защитные заголовки уже включены, загрузите новый `munchkin-vps-ip.tar.gz` тем же SCP, распакуйте в отдельный каталог и используйте **update-ip.sh**:

```bash
upload_dir=$(mktemp -d /root/munchkin-update.XXXXXX)
tar -xzf /root/munchkin-vps-ip.tar.gz -C "$upload_dir"
bash "$upload_dir/update-ip.sh"
```

Обновление сохраняет резервную копию сайта в `/opt/munchkin-hero/backups/site.XXXXXXXX`, сначала копирует новые ресурсы, затем заменяет `index.html` и `sw.js`. Старые файлы с хешами остаются для открытых клиентов. Перезапуск служб не нужен. Скрипт не меняет Caddyfile, сертификаты, systemd, firewall или настройки других служб. Партии игроков хранятся в браузерах и сохраняются; для загрузки новой версии подключите интернет и нажмите «Обновить» в приложении.

Бинарник Caddy здесь закреплён на 2.11.7. Обновления самого веб-сервера выполняются отдельно после проверки нового официального релиза; закреплённый бинарник не обновляется автоматически.

## Локальная проверка перед передачей

Конфигурация прошла `caddy validate` версии 2.11.7. `bash -n` и `systemd-analyze verify` выполнены в изолированной Ubuntu 24.04. Проверены отказ при некорректном IPv4 и занятом 80, HTTPS-раздача страницы и PWA-файлов с локальным тестовым CA, заголовки `sw.js`, HTTP-редирект и сохранение отдельного процесса на 443. Для локального TLS-теста ACME заменялся тестовым CA.

Скрипт `test-secure-update.sh` предназначен только для одноразового тестового контейнера: он создаёт тестовую установку, подменяет `systemctl` и HTTPS-проверку, проверяет отказ при неверном IP и изменённом Caddyfile, резервные копии, права, повторный запуск и откат при сбое перезапуска. Настоящая HTTPS-раздача и заголовки отдельно проверены с Caddy. Тестовый скрипт не включается в готовый архив для установки и не должен запускаться на VPS.

В отдельном тестовом развёртывании проверены доверенный сертификат, HTTP 200, production-манифест, `sw.js` с `Cache-Control: no-cache` и редирект HTTP → HTTPS. В Edge подтверждены secure context, активный Service Worker, сохранение бонуса отдельного предмета и перезагрузка без сети; ошибок JavaScript не было. Адрес сервера в публикацию не включён. Физические iPhone/Android, работоспособность существующего VPN/прокси и фактическое последующее продление сертификата проверяются владельцем отдельно.
