# Установка на свой VPS

Мастер рассчитан на **Ubuntu 24.04, x86_64 или arm64**, с systemd. На сервере нужны `curl`, `ca-certificates`, `tar` и стандартные системные утилиты. Node.js и Docker не нужны. Приложение работает на `https://ВАШ_IP:8443`; TCP 80 используется для выдачи и автоматического продления сертификата. Оба порта должны быть свободны и доступны извне.

Установщик создаёт отдельную службу и пользователя. Он не меняет firewall, SSH, Xray, telemt или действующие веб-серверы. При занятом 80/8443 мастер остановится. Для существующего HTTPS-сервера можно использовать готовые файлы из `munchkin-static.zip`.

## 1. Скачать пакет

Откройте **Releases** репозитория GitHub. Выберите опубликованный релиз и скачайте **munchkin-vps-ip.tar.gz** и **SHA256SUMS.txt** из одной версии. Встроенные GitHub «Source code» — исходники, а не готовый установщик.

На компьютере, из папки со скачанными файлами (PowerShell):

```powershell
$serverIp = Read-Host 'Публичный IPv4 вашего VPS'
scp .\munchkin-vps-ip.tar.gz .\SHA256SUMS.txt "root@${serverIp}:/root/"
ssh "root@${serverIp}"
```

Если входите не как root, загрузите файлы в домашний каталог своего пользователя и запускайте мастер через `sudo`. Пароль вводится только в локальном запросе SSH/SCP; в GitHub его добавлять не нужно.

## 2. Установить на сервере

Следующие команды выполняются **в SSH-терминале сервера**, после входа, а не в PowerShell:

```bash
cd ~
grep '  munchkin-vps-ip.tar.gz$' SHA256SUMS.txt | sha256sum --check --strict -
```

Продолжайте только при ответе **munchkin-vps-ip.tar.gz: OK**. Контрольная сумма проверяет целостность скачивания; доверяйте самому репозиторию и выбранному релизу.

```bash
upload_dir=$(mktemp -d "$HOME/munchkin-upload.XXXXXXXX")
tar -xzf munchkin-vps-ip.tar.gz -C "$upload_dir"
cd "$upload_dir"
sudo bash setup.sh
```

Выберите **1. Установить**, введите публичный IPv4 этого сервера и подтвердите. Мастер не определяет IP через сторонние сервисы. Для сертификата используется Let's Encrypt; IP попадёт в публичные журналы сертификатов. Установщик скачивает Caddy с официального GitHub и проверяет его контрольную сумму.

После установки откройте напечатанный HTTPS-адрес. Выпуск сертификата может занять время. Проверка состояния и журнала:

```bash
sudo bash setup.sh status
sudo bash setup.sh logs
```

Если сертификат не выпустился, проверьте журнал, часы сервера и доступность TCP 80/8443 в существующем firewall и панели провайдера. При ошибке сертификата не используйте обход проверки HTTPS для установки PWA. Первая загрузка и кеширование требуют интернета; затем счётчик работает офлайн.

## Обновление

Скачайте архив и контрольные суммы нового релиза. Повторите загрузку, проверку и распаковку **в новый пустой каталог** из шагов 1–2. Затем из нового каталога:

```bash
sudo bash setup.sh update
```

Перед заменой сохраняется копия сайта в `/opt/munchkin-hero/backups/`. Старые файлы ресурсов остаются доступны открытым клиентам. Caddyfile, сертификаты и службы при обычном обновлении не меняются. На телефоне подключите интернет и нажмите «Обновить» в приложении. При прежнем адресе прогресс сохраняется в браузере.

Для старой установки без защитных заголовков вместо обычного обновления выполните `sudo bash secure-update-ip.sh ВАШ_IPV4`. Скрипт проверит стандартный Caddyfile, сохранит резервные копии и перезапустит только `munchkin-hero`. Изменённые вручную конфигурации автоматически не перезаписываются.

## Управление и удаление

Откройте меню `sudo bash setup.sh`: состояние, журнал, запуск, остановка, удаление с сохранением файлов. Все команды действуют только на службу `munchkin-hero`.

Удаление требует ввода `REMOVE`. Приложение отключается, а его каталог и unit переносятся в закрытый `/opt/munchkin-hero-removed.*`. Сертификаты и пользователь службы сохраняются; мастер печатает команды восстановления. Чтобы вернуть приложение, выполните эти команды; повторная чистая установка поверх сохранённых данных намеренно запрещена. Для полного стирания оставшихся данных сначала проверьте резервные копии вручную.

Для сохранения партии на телефоне не удаляйте установленную PWA и не очищайте данные браузера. Смена IP/домена/порта создаёт другой адрес хранения, поэтому прежняя партия автоматически туда не переносится.
