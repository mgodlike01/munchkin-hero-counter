# Подготовка к GitHub

Публикуйте файлы из проверенного `munchkin-source.tar.gz` либо исходники из списка `scripts/public-files.json`. Каталог `artifacts/` целиком загружать нельзя: в нём могут быть старые архивы и личные резервные копии. Для релиза предназначены только три новых архива и `SHA256SUMS.txt`.

## Перед первым размещением

1. Создайте пустой репозиторий на GitHub. Для свободного скачивания установщика выберите публичный доступ. Не загружайте конфигурацию работающего VPS, пароли, SSH-ключи, сертификаты или `.env`.
2. Распакуйте **новый** `munchkin-source.tar.gz` в отдельную пустую папку. В нём нет Git-истории, старых сборок и резервных копий.
3. Проверьте файлы, затем загрузите их через GitHub Desktop или Git. При создании первого коммита используйте privacy email из GitHub → Settings → Emails, если не хотите публиковать личную почту в метаданных коммитов.
4. Для разрешения использования и распространения кода выберите лицензию и добавьте `LICENSE` перед открытой публикацией. Лицензии шрифтов и библиотек в `public/` сохраняйте.

Проект не содержит ссылки на сервер автора. Примеры используют `example.com`, `localhost` и выделенные адреса для документации. Значение IP для установки вводится на своём VPS и сохраняется только в его рабочем Caddyfile.

## Проверка и архивы

Нужны Node.js 24, npm и **Python 3.10+** (без сторонних Python-пакетов). В Windows команда Python обычно `python`, в Linux при необходимости используйте `python3`:

```text
npm ci
npm run check
python scripts/check-public-files.py
python scripts/test-public-files.py
python scripts/package-vps.py
```

При работе с Git дополнительно запустите `python scripts/check-public-files.py --tracked`. Этот режим проверяет также все файлы, добавленные в индекс Git. Проверка останавливает сборку при обнаружении IP вне localhost/примеров, абсолютных Windows-путей, личных домашних каталогов и распространённых форматов секретов; значения совпадений не печатаются в журнал. Это проверка по правилам, а не гарантия обнаружения любых личных данных — просмотрите новые файлы и тексты самостоятельно.

Упаковщик читает явный список публичных файлов, отклоняет символические ссылки и приватные имена, проверяет готовый `dist/`. Архивы имеют только относительные пути и обезличенные метаданные владельца. Старые приватные данные в игнорируемых каталогах не включаются.

## Автоматическая сборка

Workflow **Checks** проверяет публичные файлы, тесты, сборку, браузерные сценарии и готовит архивы при push/PR. Workflow **Release** запускается при push тега `v*`, например `v1.0.0`. Версия тега должна совпадать с `package.json`.

Release создаёт **черновик релиза** с готовыми `munchkin-vps-ip.tar.gz`, `munchkin-static.zip`, `munchkin-source.tar.gz` и `SHA256SUMS.txt`. В GitHub → Releases откройте черновик, проверьте описание и нажмите **Publish release**. После публикации этой страницей можно делиться; SSH-доступ к вашему VPS пользователям не нужен.

Сборка работает на GitHub и не подключается к VPS. Доступ по SSH, серверные IP, пароли и собственные токены в GitHub Secrets для неё не нужны: используется временный `GITHUB_TOKEN`. Право записи есть только у workflow релиза.

Если личные данные уже попали в коммиты или старые релизы, удаление из текущих файлов не убирает их из истории и скачанных копий. До первой публикации здесь подготовлен отдельный архив без истории; для уже опубликованного репозитория историю и старые вложения нужно проверить отдельно.
