# Манчкин — Счётчик героя

Персональный счётчик для настольной игры. React + TypeScript + Vite, Tailwind CSS, Lucide и `vite-plugin-pwa`. Работает без сервера, аккаунтов, внешних API, рекламы и аналитики. Все шрифты и изображения поставляются локально. Оригинальная иконка создана для этого проекта; официальные материалы игры не используются.

Уведомления и лицензии используемых библиотек и шрифтов: [public/third-party-notices.txt](public/third-party-notices.txt).

## Установка на своём сервере и GitHub

Скачайте `munchkin-vps-ip.tar.gz` и `SHA256SUMS.txt` из **Releases** этого репозитория. Готовый пакет устанавливается без Node.js и Docker на сервере. Пошаговый мастер: [INSTALL.md](INSTALL.md). IP вводится при установке и не записывается в исходники GitHub.

Для выпуска релиза и проверки файлов перед публикацией: [PUBLISHING.md](PUBLISHING.md). Автоматическая сборка не использует SSH и не подключается к VPS.

Оформление выполнено в духе приключенческих настольных карточек: пергамент, чернильные контуры, красные акценты и рукописный шрифт Neucha с кириллицей. Для новых пользователей выбрана светлая тема, сохранённый выбор темы не меняется. Тёмная тема использует матовый графитовый фон, приглушённый серо-бежевый текст и мягкие рамки. Иконка с рогатым шлемом нарисована отдельно для приложения; готовые изображения и шрифты доступны офлайн.

## Требования

- Node.js 22.12+ (рекомендуется Node.js 24) и npm.
- VS Code или другой редактор.
- Для Docker-развёртывания: Docker Engine/Desktop с Compose.
- Для установки PWA на телефоне: HTTPS с доверенным сертификатом на домен или IP. `http://localhost` подходит для проверки на компьютере. Обычный HTTP по LAN/публичному IP не включает Service Worker на телефоне.
- Современный браузер; для минимальных целевых версий интерфейса — Safari/iOS 16.4+ и актуальный Chromium. Реальные устройства нужно проверить отдельно.

## Быстрый запуск в VS Code

Откройте папку проекта, выберите **Терминал → Создать терминал** и выполните:

```powershell
npm ci
npm run dev
```

Откройте напечатанный Vite адрес, обычно `http://localhost:5173`. Сервер также слушает локальную сеть для просмотра интерфейса с телефона. В режиме разработки Service Worker отключён, чтобы не мешать обновлению файлов.

## Как пользоваться

- `−` / `+` изменяют число; нажатие на число позволяет ввести его вручную. Ввод применяется при Enter или уходе из поля. Некорректный ввод отменяется, выход за диапазон ограничивается допустимыми границами.
- Уровень: 1–10, в эпическом режиме: 1–20. Ручные бонусы: 0–999, модификатор: −999…999. Это технические пределы интерфейса; общая сила может быть отрицательной.
- Боевая сила = уровень + постоянные бонусы + временный модификатор.
- На главном экране — компактная сетка снаряжения: головняк, броня, обувка, правая/левая рука, другие бонусы. У каждой иконки слева «−», справа «+», под иконкой — бонус. Нажатие на иконку включает предмет в силу или убирает в запас. Сетка по две вещи в ряд адаптирована к телефонам шириной от 320 px; на коротких экранах доступна вертикальная прокрутка.
- Первое изменение предмета включает подсчёт по вещам. Ручная сумма при первой настройке переносится в «Другие бонусы». Если уже сохранённый список отличается от выбранной ручной суммы, перед переходом требуется подтверждение.
- Через значок настроек у снаряжения можно вручную ввести число, указать название, выбрать ручной режим, добавить или удалить дополнительные вещи с подтверждением; до 32 обычных предметов плюс два спутника в расширенной версии, бонус каждого — 0–999.
- В режиме по предметам постоянный бонус складывается автоматически только из включённых вещей; ручной бонус к нему не прибавляется. При первом включении старая сумма переносится в «Другие бонусы». Затем ручная сумма и список сохраняются отдельно; смена режима с другой суммой требует подтверждения. Двуручное оружие учитывайте в одной руке, вторую оставляйте пустой; свойства/ограничения карт приложение не проверяет.
- Круговая стрелка рядом с модификатором сбрасывает только его.
- Сравнение с монстром и кнопка завершения боя убраны. Награду за победу игрок добавляет сам; временные модификаторы сбрасываются отдельной стрелкой.
- Шестерёнка открывает версию игры, эпический режим, тему и виброотклик. Версия «Наёмники и скакуны» автоматически добавляет два отдельных слота с иконками и счётчиками бонусов; базовая версия показывает обычное снаряжение.
- В настройках находятся **«Обучение»** и **«Документация»**. При первом знакомстве на главном экране появляется предложение пройти короткий урок; «Позже» скрывает его, повторный запуск всегда доступен в настройках.
- Обучение подсвечивает настоящие кнопки и предлагает нажать их: добавить уровень, открыть снаряжение, включить учёт по предметам, добавить и удалить вещь, подтвердить удаление, вернуться к герою и найти настройки со справкой. Оно использует отдельную учебную партию в памяти: основной герой не меняется даже при закрытии или перезагрузке. Выход — крестик на подсказке, Escape или системное закрытие учебного окна.
- Документация доступна без интернета и описывает все функции счётчика: расчёт силы, способы учёта бонусов, снаряжение и запас, спутников, модификаторы, кубик, новую партию, настройки, установку, обновления и сохранения.
- При возврате к базовой версии наёмник и скакун скрываются, их бонусы не участвуют в сумме предметов. Названия, бонусы и состояние запаса сохраняются и возвращаются при повторном включении расширенной версии. Ручная сумма бонусов остаётся под контролем игрока.
- Кнопка **«Новая партия»** находится на главном экране под снаряжением. Сброс требует подтверждения.
- Рядом находится **«Кубик D6»**: нажатие сразу бросает кубик и открывает результат от 1 до 6, повторный бросок доступен в том же окне. Броски работают офлайн, используют локальный генератор случайных чисел браузера и не меняют показатели или сохранение героя.
- Новая партия сбрасывает игровые числа, названия и бонусы всего снаряжения, включая скрытых спутников. Версия игры, тема, способ учёта снаряжения, эпический режим, правило равенства и виброотклик сохраняются.
- Возврат из эпического режима при уровне выше 10 требует подтверждения: уровень станет 10.
- Вибрация применяется только при поддержке браузером; отсутствие Vibration API не мешает работе.

В ручном режиме предел бонусов — 999. В режиме по предметам сумма может быть больше: до 32 × 999 в базе и 34 × 999 с наёмником и скакуном. Эти два слота не занимают места у прежних 32 предметов. Сумма отображается как готовый результат и не ограничивается ручным счётчиком.

## Сборка и проверки

```powershell
npm run typecheck
npm test
npm run build
npm run preview
```

`npm run check` запускает модульные тесты, TypeScript и production-сборку. Готовые статические файлы появляются в `dist/`. Предпросмотр обычно доступен на `http://localhost:4173`.

Браузерные тесты используют Playwright и production-сборку:

```powershell
npx playwright install chromium
npm run build
npm run test:e2e
```

Можно использовать уже установленный Edge без загрузки браузера:

```powershell
$env:PLAYWRIGHT_EXECUTABLE_PATH = Join-Path ${env:ProgramFiles(x86)} 'Microsoft\Edge\Application\msedge.exe'
npm run test:e2e
```

В Linux/macOS путь передаётся обычной переменной окружения `PLAYWRIGHT_EXECUTABLE_PATH`. Без неё Playwright использует свой Chromium. E2E-тесты проверяют ввод и границы, сохранение после перезагрузки, счётчики предметов, настройки, подтверждения, отсутствие импорта/экспорта, CSP и безопасный вывод названий, недоступное хранилище, повреждённое сохранение, экраны от 320×568 до 1440×1000, размеры кнопок, запуск офлайн и обновление Service Worker с сохранением партии. Тест обновления временно меняет `dist/sw.js` и восстанавливает его; запускайте его на локальной сборке, которую никто не публикует одновременно.

`npm run audit` проверяет зависимости и завершается с ошибкой при известных проблемах среднего уровня и выше. Аудит при установке тоже включён. Остаточное замечание низкого уровня и границы проверки описаны в [SECURITY-REVIEW.md](SECURITY-REVIEW.md).

Иконки уже включены в `public/`. Для их пересоздания из `public/icon.svg`:

```powershell
npm run icons
```

Создаются обычные PNG 192/512 px, Apple Touch 180 px и отдельная maskable-иконка 512 px с безопасными отступами. Манифест ссылается на версионированные `hero-v2-*`, а HTML — на `apple-touch-icon-hero-v2.png`; прежние пути также обновляются для совместимости. Скругление применяет система, сами PNG имеют непрозрачный квадратный фон.

## Docker и VPS

**Если на VPS работает Xray/3x-ui, сначала используйте [инструкцию по совместному размещению](deploy/VPS-XRAY.md).** Она учитывает занятый 443, локальный порт приложения, отдельный Compose-проект и вариант без установки Docker.

Для **Ubuntu 24.04 и доступа по IP** подготовлен [отдельный установщик на Caddy](deploy/ip/README.md): HTTPS на 8443, IP-сертификат Let's Encrypt с автоматическим продлением через порт 80, отдельная systemd-служба. Docker и Node.js на VPS не требуются. Службы на 443 сохраняют свои порты.

Multi-stage `Dockerfile` выполняет `npm ci`, модульные тесты, TypeScript и сборку в Node.js. Итоговый контейнер содержит только Nginx и статические файлы. Backend и база данных не нужны.

```sh
docker compose up -d --build
docker compose ps
```

Приложение доступно на `http://localhost:8080` на машине с Docker. Compose привязывает порт только к `127.0.0.1`. Переменная `MUNCHKIN_HTTP_PORT` в `.env` меняет его; для VPS есть образец `deploy/vps.env.example` с портом 18080. Проверьте, что выбранный порт свободен. Для внешнего доступа нужен HTTPS-прокси.

Пример `deploy/Caddyfile` предназначен для нового сервера со свободными 80/443: замените домен, направьте DNS A/AAAA на VPS и настройте Caddy. Он автоматически выдаёт сертификат и проксирует на `127.0.0.1:8080`. На сервере с Xray или работающим прокси не заменяйте существующий Caddyfile и не запускайте второй listener на занятом 443; используйте отдельную инструкцию выше.

Обновление:

```sh
docker compose up -d --build
```

Контейнер не хранит партии: они находятся в браузерах игроков и не удаляются при пересборке.

Альтернатива без Docker: `npm ci && npm run build`, затем раздавайте содержимое `dist/` через Nginx/Caddy. `deploy/nginx.conf` — готовая конфигурация статической раздачи для контейнера; для VPS измените `root` и `server_name`, добавьте TLS либо поставьте Nginx за HTTPS-прокси. Сайт рассчитан на корень отдельного домена, не на подпапку.

`index.html`, манифест и `sw.js` должны перепроверяться, а файлы с хешами в `/assets/` могут кешироваться год. Эти заголовки настроены в Nginx. При обновлении приложение показывает предложение **Обновить**: новая версия активируется только после нажатия. Текущие показатели к этому моменту уже записаны в localStorage.

В PowerShell из папки проекта после успешной проверки сборки:

```powershell
npm run build
.\scripts\package-vps.ps1
```

`munchkin-static.zip` содержит готовый сайт, `munchkin-source.tar.gz` — исходники для Docker, `munchkin-vps-ip.tar.gz` — сайт и отдельный установщик HTTPS по IP для Ubuntu. Рядом создаётся `SHA256SUMS.txt`. Кеши, `node_modules`, локальная `.env` и данные браузера в архивы не попадают. Следуйте [инструкции для VPS с Xray](deploy/VPS-XRAY.md) или [установке по IP](deploy/ip/README.md).

2. Дождитесь подписи **Готово к офлайну** под счётчиком.
3. Нажмите **На главный экран** в приложении и **Установить приложение**, если кнопка доступна. Или откройте меню Chrome ⋮ → **Добавить на главный экран** → **Установить**. Названия пунктов могут немного отличаться.
4. Запустите приложение с появившейся иконки.

1. Откройте production-сайт по HTTPS в Safari.
2. Дождитесь подписи **Готово к офлайну**.
3. Нажмите **Поделиться** → **На экран «Домой»** / **Добавить на экран «Домой»**.

Новую иконку для добавления в Safari задаёт отдельный PNG в `apple-touch-icon`.

[Инструкция Apple по установке веб-приложения](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios).

## Проверка офлайн-режима

1. Используйте `npm run build` и `npm run preview` на localhost или production-сайт по HTTPS. Dev-сервер для этого не подходит.
2. При подключённой сети откройте приложение и дождитесь **Готово к офлайну**. Service Worker должен закончить первоначальное кеширование.
3. Измените уровень и бонусы. В DevTools → Application → Service Workers убедитесь, что воркер активен; в Cache Storage — что присутствует precache Workbox.
4. Включите Offline в DevTools → Network либо авиарежим на телефоне. Перезагрузите страницу, закройте и снова запустите установленное приложение.
5. Проверьте сохранение показателей, изменение счётчиков и доступность настроек. Подпись должна измениться на **Без интернета**.
6. Снова включите сеть. После публикации новой сборки вернитесь в приложение: оно проверит обновление при фокусе. Нажмите **Обновить** и проверьте, что партия осталась.

Кеш содержит оболочку, JS, CSS, локальные шрифты и иконки. Игровые данные никогда не записываются в Service Worker Cache. Приложение не делает запросов к внешним сервисам. Для самого первого открытия нужен интернет; автономный запуск возможен после успешного первоначального кеширования.

## Автоматическое сохранение

Все изменения синхронно записываются в localStorage под ключом `munchkin.hero.v1`. Отложенной записи нет. Обычное обновление приложения и Service Worker не сбрасывает партию.

Текущая схема — **v2**. Ключ localStorage оставлен прежним ради совместимости. Локальные сохранения v1 автоматически переводятся в ручной режим v2 без потери уровня, бонусов, модификатора и настроек. У старых сохранений v1/v2 без `gameEdition` выбирается базовая версия. Поля монстра и правила равенства читаются в старых данных ради совместимости, в интерфейсе их больше нет. Импорт и экспорт файлов удалены; данные остаются только в браузере.

```json
{
  "schemaVersion": 2,
  "level": 1,
  "equipmentBonus": 0,
  "equipmentMode": "manual",
  "gameEdition": "base",
  "equipmentItems": [],
  "temporaryModifier": 0,
  "monsterPower": 0,
  "epicMode": false,
  "heroWinsTies": false,
  "theme": "dark",
  "haptics": true
}
```

- Максимальный размер локального сохранения — 32 КБ. Неизвестные поля отбрасываются; будущие версии схемы не принимаются. Для исходного формата v1 без `theme` и `haptics` применяются тёмная тема и включённая вибрация.
- `gameEdition` принимает `base` или `companions`; отсутствующее поле означает базовую версию. В `equipmentItems` хранятся `id`, `slot` (`head`, `armor`, `boots`, `hand1`, `hand2`, `other`, `hireling`, `steed`), `name`, `bonus`, `equipped`. Проверяются типы, длина названия до 64 символов, уникальность ID и диапазоны. Предел — 32 обычных предмета и два зарезервированных спутника (`slot-hireling`, `slot-steed`). Повреждённый список не заменяет текущую партию.
- При повреждённых/неподдерживаемых локальных данных исходная строка сохраняется в `munchkin.hero.recovery`, показывается предупреждение, открывается безопасная новая партия. Резерв доступен через DevTools → Application → Local Storage; автоматического восстановления из него нет.
- Если хранилище запрещено или переполнено, счётчик работает в памяти и показывает предупреждение. Разрешите хранение данных в настройках браузера; до успешного сохранения показатели могут потеряться при закрытии или перезагрузке.
- Очистка данных сайта, удаление приложения и смена адреса могут удалить или изолировать браузерное хранилище. Автоматической синхронизации между устройствами нет.

## Структура

```text
src/
  components/     Счётчики, панели, модальные окна
  pages/          Главный экран
  hooks/          Игровое состояние, установка и обновление PWA
  store/          Чистый reducer действий
  services/       Валидация и localStorage
  types/          Типы состояния и действий
  utils/          Расчёт силы, сравнение и диапазоны
  styles/         Темы, Tailwind и адаптивная вёрстка
public/           Оригинальные иконки
scripts/          Генерация PNG из SVG
tests/            Браузерные сценарии production PWA
deploy/           Nginx и пример HTTPS-прокси Caddy
```

Модульные тесты расположены рядом с логикой. Для расширения формата сохранений добавляйте явную миграцию в `services/save.ts`; не удаляйте localStorage во время обновлений.
